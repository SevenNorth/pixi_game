# 雷电法王皮卡丘：玩法与技术规划

> 状态：Phaser 阶段零已完成
>
> 更新时间：2026-08-10
>
> 当前基线：Phaser 3.90.x + TypeScript + Vite + DOM HUD

## 1. 项目定位

将当前的 2D 动作小游戏扩展为一款偏 Roguelite 的“无限生存 + 单局构筑 + 地图推进”游戏。玩家应在每局中通过有限候选做出可感知的构筑选择，而不是只依靠固定数值自动成长。

玩家控制皮卡丘在无限世界中移动、探索、躲避障碍物和追踪型怪物，使用攻击击杀怪物并获取经验，通过食物获得临时效果，通过升级和满级后的强化选择构建角色能力，尽可能长时间生存。

## 2. 核心循环

```text
移动探索
  -> 躲避障碍物和怪物
  -> 收集食物，恢复生命
  -> 攻击并击杀怪物，获得经验
  -> 升级，获得基础属性并进行技能三选一
  -> 击杀怪物和探索新区块，积累全局地图经验
  -> 地图经验满后挑战 Boss，提升全局地图等级
  -> 满级后通过击杀获得被动强化选择
  -> 新生成怪物按地图等级范围增强
  -> 血量耗尽，游戏结束
```

## 3. 已确定的玩法方向

### 3.1 无限世界

- 使用无限逻辑世界，不创建无限大的 Canvas。
- 玩家使用世界坐标移动，摄像机跟随玩家。
- 只加载和渲染玩家附近区域。
- 地图建议按区块生成，例如 `512 x 512` 一个区块。
- 远离玩家的对象需要销毁、回收或转为轻量逻辑数据。

### 3.2 障碍物

- 世界中随机生成静态障碍物。
- 障碍物至少影响玩家移动和敌人移动。
- 第一版暂不引入复杂动态陷阱。
- 玩家出生点附近必须保留安全区域。
- 食物和敌人不能生成在明显不可达或不公平的位置。
- 地图随机最好支持种子，以便复现问题和调试。

### 3.3 食物回血道具

食物只负责立即恢复生命，不再承担护盾、移动速度、攻击速度或经验倍率等临时效果，也不再用于增加分数。当前恢复值：

- 苹果、香蕉：恢复 1 点生命。
- 面包、奶酪、草莓：恢复 2 点生命。
- 恢复量不能超过玩家最大生命。

现有本地食物图片暂时继续使用。后续替换资源时，使用统一画风、透明背景和稳定尺寸的回血食物图标。

### 3.4 功能道具和外观语义

护盾、加速、攻速、经验倍率等效果未来使用独立功能道具，图片必须直接表达效果，例如护盾碎片、疾速靴、充能电池或经验晶体。功能道具与食物使用不同的数据定义和掉落池，不能再用无关食物图片承载战斗增益。

### 3.5 经验和升级

- 击杀怪物获得经验。
- 经验进入角色经验条。
- 达到阈值后升级。
- 升级先结算基础属性，并恢复 1 点当前血量。
- 每次升级都生成一次技能三选一；奖励覆盖层打开时暂停模拟，选择完成后继续游戏。
- 一次经验结算造成连续升级时，按升级次数进入待选奖励队列，逐次选择，不合并为一次奖励。

角色升级提供稳定成长，但不让所有属性自动提高：

- 最大生命每级 `+1`。
- 攻击力每两级 `+1`，即 Lv.3、Lv.5、Lv.7、Lv.9 提升。
- 护盾上限在 Lv.5、Lv.10 各 `+1`。
- 移动速度、攻击速度和技能冷却不随等级自动成长，保留给食物和被动技能构筑。

### 3.6 血量和护盾

血量和护盾都按“点”计算：

```text
受到伤害
  -> 先扣护盾
  -> 剩余伤害扣当前血量
  -> 血量 <= 0，游戏结束
```

建议模型：

```ts
interface VitalStats {
  hp: number;
  maxHp: number;
  shield: number;
  maxShield: number;
}
```

建议初始规则：护盾是短期防御资源，不快速自动恢复；受伤后提供 `1s` 无敌时间并持续闪烁，避免连续碰撞瞬间扣空血量。怪物接触玩家造成伤害后不会消失，而是被推离玩家并继续参与战斗。

### 3.7 被动技能和满级强化

- 角色等级有上限。
- 达到满级后，继续击杀一定数量的怪物可触发强化选择。
- 首次满级强化需要击杀 12 只非 Boss 怪物，之后每次需求增加 4；角色经验条在满级后切换为该击杀进度。
- 满级强化统一归入被动技能，不再建立一套重复的“永久强化”系统。
- 被动技能不同于食物恢复和未来的功能道具，在本局游戏中永久生效。
- 每次提供若干候选强化，玩家选择一个。
- 初始拥有 4 个被动槽位，特殊奖励最多扩展到 6 个。
- 相同被动重复获得时提升等级，不额外占用槽位。
- 被动槽位达到上限后，允许放弃新被动或替换已有被动；替换需要二次确认。

候选被动技能：

- 攻击力增加
- 技能伤害增加
- 子弹穿透增加
- 子弹数量增加
- 基础攻击间隔减少
- 技能冷却减少
- 移动速度永久提升
- 护盾上限增加
- 受到伤害降低
- 经验获取增加
- 食物持续时间增加

### 3.8 怪物难度成长

怪物难度至少包含三个维度：

- 血量点数随怪物自身等级提升
- 移动速度随怪物自身等级提升
- 出现数量增加，生成间隔缩短

怪物等级不直接跟随玩家等级。全局地图等级决定新生成怪物的等级范围和权重；已经生成的怪物保持出生时的等级和属性，地图升级不会原地强化场上怪物。

示例分布：

```text
地图 Lv.1：怪物 Lv.1 85%，Lv.2 15%
地图 Lv.2：怪物 Lv.1 30%，Lv.2 55%，Lv.3 15%
地图 Lv.3：怪物 Lv.2 30%，Lv.3 55%，Lv.4 15%
```

怪物需要拥有独立血量、最大血量、伤害、速度和经验奖励。怪物还具有按类型配置的巡视、仇恨和最大追击范围，并使用进入/脱离两个半径避免在边界反复切换：

| 类型 | 体型 | 基础移速 | 巡视半径 | 仇恨进入 | 仇恨脱离 | 最大追击 |
|---|---:|---:|---:|---:|---:|---:|
| 普通怪 | `1x` | 98 | 160 | 320 | 440 | 600 |
| 精英怪 | `2x` | 82 | 240 | 420 | 560 | 760 |
| Boss | `3.5x` | 58 | 320 | 560 | 720 | 960 |

未进入仇恨状态时，怪物不会静止不动，而是在出生点周围按类型配置的范围内随机巡视；到达目标点后停留约 `300-700ms` 再选择下一个目标。体型与基础移动速度负相关，地图等级带来的动态速度修正留给难度导演处理。

怪物行为状态为 `idle -> chasing -> returning -> idle`。`returning` 是独立状态：怪物达到最大追击距离或脱战后先返回出生点，回到出生点前不重新进入仇恨，避免追击和回家在相邻帧反复切换导致动画抖动或原地卡住。

建议后续引入“难度预算”而不是单纯堆数量：

```text
ThreatBudget = 基础预算 + 地图等级系数 + 存活时间小幅系数
```

不同怪物类型消耗不同预算，以便控制整体压力和性能。

### 3.9 全局地图等级和 Boss 门槛

地图等级是本局游戏的全局难度，不划分区域等级。无限世界仍然可以使用区块做生成、回收和探索记录，但区块只是技术与探索单位，不拥有独立等级。

玩家等级、地图等级和怪物等级是三套独立数据：

- 玩家等级：决定角色基础属性和角色成长。
- 地图等级：决定怪物等级分布、生成压力、掉落档位和 Boss 强度。
- 怪物等级：在生成时由地图等级加权抽取，决定该怪物的血量、速度、伤害和基础奖励。

地图使用独立经验条。地图经验同时来自两类行为：

- 击杀怪物：根据怪物等级提供地图经验。
- 探索新区块：首次进入未发现区块时提供一次地图经验，重复往返不再获得。

探索经验应设置阶段占比上限，避免玩家只跑图、不战斗就填满地图经验；建议每个地图等级最多有约 30% 到 40% 的经验来自探索，其余必须通过战斗获得。

地图经验满后不会自动升级，而是进入 `boss-ready` 状态：

```text
积累地图经验
  -> 地图经验达到上限并停止增长
  -> Boss 挑战可用，普通战斗继续
  -> 击杀 Boss
  -> 全局地图等级 +1
  -> 地图经验归零，刷新怪物等级分布和奖励档位
```

Boss 出现不应暂停或强制切断当前战斗。第一版可以在玩家附近生成明确可见的 Boss 挑战入口，由玩家主动开始。未击杀 Boss 前：

- 全局地图等级不变。
- 新怪物仍按当前地图等级生成。
- 地图经验保持满值，不会溢出或提前计入下一级。
- 玩家仍可获得角色经验，但等级差收益衰减会逐渐降低原地刷怪效率。

Boss 的属性以当前地图等级为基准，不动态追随玩家等级。这样玩家可以通过角色成长降低挑战难度，但不能只靠升级绕过 Boss 推进门槛。击杀 Boss 后应提供一次明确的高价值奖励，并解锁更高档位的普通掉落。

建议状态模型：

```ts
interface MapProgressionState {
  level: number;
  experience: number;
  experienceToNext: number;
  status: 'progressing' | 'boss-ready' | 'boss-active';
  explorationExperience: number;
  explorationExperienceCap: number;
}
```

### 3.10 玩家与地图等级匹配

奖励倍率使用“玩家等级 - 地图等级”的差值计算，而不是让怪物强行跟随玩家：

- 玩家等级接近地图等级：获得正常经验和掉落。
- 玩家明显高于地图等级：角色经验减少，低价值掉落增多，高档掉落概率降低。
- 地图等级高于玩家等级：经验和掉落质量适度提高，奖励越级挑战，但倍率需要封顶。

建议先使用容易调试的分段规则：

```text
玩家比地图低 2 级及以上：角色经验 x1.30，掉落品质小幅提高
等级差在 -1 到 +1：角色经验 x1.00，正常掉落
玩家比地图高 2 级：角色经验 x0.70，优质掉落概率降低
玩家比地图高 3 级：角色经验 x0.45，只保留少量优质掉落
玩家比地图高 4 级及以上：角色经验 x0.25，优质掉落极少
```

地图经验不受玩家与地图等级差惩罚，否则玩家落后于推进节奏时可能无法继续解锁 Boss。掉落的基础档位先由地图等级决定，再应用等级差修正。

### 3.11 敌人分层、外观和技能

敌人分为普通怪、精英怪和 Boss，三者承担不同的战斗职责：

| 类型 | 外观方案 | 战斗方式 | 主动技能 |
| --- | --- | --- | --- |
| 普通怪 | 保留现有 Sprite | 追踪和接触伤害 | 0 |
| 精英怪 | 程序化外观，或 Sprite 加绘制部件 | 接触或远程攻击 | 第一版 1 个，后期最多 2 个 |
| Boss | 组合式程序化绘制 | 基础远程攻击和阶段行为 | 第一版 2 个，后期最多 3 个 |

程序化外观使用“主体形状 + 附属部件 + 配色 + 尺寸 + 动画方式”组合出不同形象。大量敌人不应每帧重新绘制；应使用 Phaser `Graphics` 生成外观后缓存为 Texture，再作为 Sprite 渲染。Boss 的少量活动部件可以使用 `Container + Graphics` 单独动画。所有碰撞体使用明确的逻辑尺寸，不依赖绘制边界。

精英怪和 Boss 共用技能执行框架：

```text
idle -> chasing -> windup -> casting -> recovery -> chasing
```

- 基础远程攻击不计入 Boss 的 2-3 个技能名额。
- 技能必须具有前摇预警、释放、后摇和冷却。
- 预警使用方向线、危险区域、身体闪烁等明确提示，避免无法躲避的瞬发伤害。
- 第一版精英怪只装备 1 个技能；地图等级提高后再允许少数精英怪拥有 2 个。
- 第一版 Boss 使用基础射击和 2 个技能，行为稳定后再增加第三技能或阶段变化。
- 普通怪保持现有行为，不获得远程攻击和技能。

第一批可复用敌方技能：单发或三连弹、蓄力冲锋、范围冲击波、临时护盾、召唤普通怪、持续危险区域。Boss 可以组合其中两项，精英怪只取其中一项。

玩家弹丸与敌方弹丸必须通过阵营区分，而不是分别写死碰撞逻辑：

```ts
interface ProjectileState {
  id: string;
  ownerId: string;
  faction: 'player' | 'enemy';
  damage: number;
  velocityX: number;
  velocityY: number;
}
```

### 3.12 玩家基础属性和伤害

玩家需要独立攻击力。怪物拥有点数血量后，基础攻击和主动技能都基于玩家攻击力计算：

```ts
interface PlayerBaseStats {
  level: number;
  attack: number;
  maxHp: number;
  maxShield: number;
  moveSpeed: number;
  basicAttackCooldown: number;
}
```

第一版基础值和等级成长：

| 等级 | 攻击力 | 最大生命 | 护盾上限 |
| --- | ---: | ---: | ---: |
| Lv.1 | 1 | 3 | 3 |
| Lv.3 | 2 | 5 | 3 |
| Lv.5 | 3 | 7 | 4 |
| Lv.7 | 4 | 9 | 4 |
| Lv.9 | 5 | 11 | 4 |
| Lv.10 | 5 | 12 | 5 |

伤害规则：

```text
基础攻击伤害 = 玩家最终攻击力
主动技能伤害 = round(玩家最终攻击力 x 技能倍率 + 技能固定伤害)
```

最终属性按固定顺序计算：等级基础值，加上被动固定值，再应用被动百分比和食物临时倍率，最后应用属性上限。冷却缩减第一版最多 `50%`。

基础攻击间隔为 `500ms`，理论最高攻速为每秒 2 发。玩家等级不自动提升攻击速度；未来的攻速被动和对应功能道具通过统一的攻击间隔公式生效。

怪物继续使用整数点数血量。普通怪的基准目标是同等级玩家使用约 2-3 次基础攻击击杀：

```ts
normalMaxHp = monsterLevel + 1;
maxHp = Math.round(normalMaxHp * speciesHpMultiplier * rankHpMultiplier);
```

- 快速怪可以使用较低种类倍率，重型怪使用较高倍率。
- 精英怪可从普通怪基准的约 4-6 倍开始调试。
- Boss 不只套固定倍率，应根据目标战斗时长、玩家预期每秒伤害和战斗阶段单独配置。
- 玩家用桃心展示血量；怪物仍使用血条展示，不需要把每一点绘制为独立图标。
- 第一版不加入防御力、暴击率和元素抗性，先验证攻击力与点数血量的基础节奏。

### 3.13 玩家移动和朝向

玩家支持方向键和 WASD 的八方向移动。输入先转换为二维向量，不使用带优先级的 `else if`：

```text
x = right - left
y = down - up
```

- 左右或上下同时按住时，对应轴抵消为 `0`。
- 斜向输入必须归一化，再乘移动速度，避免斜向速度变为直线速度的约 `1.414` 倍。
- 第一版立即响应输入，不增加惯性或加速度。
- 障碍物碰撞后应允许沿边缘滑动。

移动和攻击朝向分别保存：

```ts
interface PlayerDirectionState {
  movementVector: { x: number; y: number };
  facingVector: { x: number; y: number };
}
```

`movementVector` 表示当前移动输入；`facingVector` 保存最近一次有效移动、锁定目标或瞄准方向，停止移动后仍然保留。自动基础攻击优先使用当前攻击目标的方向，方向技能和位移技能使用鼠标瞄准方向；没有有效瞄准输入时回退到 `facingVector`。

角色继续复用现有四方向 Sprite 动画。斜向移动时根据主要轴选择上、下、左、右动画；两个分量相同时优先保持最近动画朝向，避免动画在两个方向间抖动。后续手柄摇杆直接复用归一化方向向量。

### 3.14 玩家主动技能和输入交互

当前已实现的键盘兼容方案是 `Space` 按住基础攻击，`J/K/L` 或 `1/2/3` 释放三个技能槽。该方案暂时保留，但不再作为目标主交互。

目标主交互采用更符合 Survivor-like Roguelite 的自由移动和智能自动攻击：

```text
移动：WASD（方向键保留为兼容键）
基础攻击：自动攻击有效目标
目标锁定/方向瞄准：鼠标
技能槽 1 / 2 / 3：Q / E / R
技能备用键：1 / 2 / 3
暂停：P
```

玩家保持八方向自由移动，不采用 `W/S` 前后移动、`A/D` 原地转向的坦克控制。基础攻击由攻击间隔驱动，按“玩家锁定目标 > 当前仍有效的目标 > 射程内最近目标”选择目标。目标死亡、离开射程或被不可穿透障碍阻断后才重新搜索，避免每发子弹在多个怪物之间抖动；没有有效目标时保持攻击就绪，新目标进入射程后可以立即开火。Boss 可以获得较高的候选权重，但不得强制覆盖玩家锁定。

鼠标点击怪物可以锁定目标，点击空地可以清除锁定；方向型主动技能读取鼠标世界方向，没有鼠标方向时回退到当前目标方向或 `facingVector`。键盘兼容模式下，`Space` 仍可按当前面向强制攻击，`J/K/L` 暂时继续可用。HUD 主要展示 `Q/E/R` 和 `1/2/3`，不为自动基础攻击长期占用一个按键提示位。

这套映射让左手始终停留在移动和技能区，右手只在需要锁定目标或瞄准方向技能时使用鼠标；相比 `J/K/L`，释放技能时不需要把任意一只手移离主要操作区。暂不把右键绑定为必需技能键，避免浏览器上下文菜单、触控板和单键鼠标造成差异。后续加入按键设置时，所有物理键都允许重绑，文档中的键位只作为默认值。

输入层只暴露 `move`、`aim`、`basic-attack`、`skill-1`、`skill-2`、`skill-3`、`confirm`、`cancel` 等 action，技能系统不直接判断物理按键。普通战斗与奖励选择使用不同输入上下文：奖励覆盖层打开时，鼠标点击或 `1/2/3` 选择候选，战斗 action 不得穿透到 Phaser Scene。第一版技能只使用冷却，不增加法力或能量资源。

技能瞄准规则：

- 方向技能朝角色面向方向释放。
- 锁定技能自动选择有效范围内最近目标。
- 范围技能以玩家为中心释放。
- 位移技能优先使用当前移动方向，没有移动输入时使用面向方向。

主动技能来源：

- 开局自带 1 个主动技能。
- 每次角色升级提供普通主动/被动技能三选一。
- 精英怪较低概率掉落技能核心，提供普通技能选择。
- Boss 必定提供一次技能选择，并可包含高品质或 Boss 专属技能。
- 获得已有技能时提升技能等级，不重复占用槽位；满级技能从对应奖励池移除。

角色可以记录本局已学会的主动技能，但同时只能装备 3 个。建议已学技能上限先设为 6 个；超过上限时才要求遗忘。获得新技能时可以装备、暂存或放弃；技能只能在奖励选择界面、Boss 入口或地图升级后的安全阶段更换，不能通过战斗中暂停随时切换。新装备技能从完整冷却开始。

第一批玩家主动技能候选：连锁闪电、电光冲刺、雷霆护盾、范围落雷、电磁领域。

精英技能核心的基础概率按有效奖励档位为 `20% / 24% / 28% / 32% / 36%`，再乘玩家与地图等级差提供的高品质概率系数，最终限制在 `2% - 50%`。第一版在精英怪死亡时直接进入奖励队列，不额外生成需要拾取的地图实体；Boss 击杀则必定进入一次 Boss 奖励。

HUD 底部固定显示三个主动技能槽，包括技能图标、`Q/1`、`E/2`、`R/3` 按键提示、冷却遮罩和剩余秒数。未装备槽位保持固定尺寸，不能因技能状态变化推动 HUD 布局。

### 3.15 玩家被动技能

被动技能就是原规划中的永久强化，与主动技能、食物恢复和功能道具分别管理：

- 被动技能在本局永久生效，不需要按键释放。
- 初始 4 个槽位，特殊奖励最多扩展到 6 个。
- 相同被动重复获得时升级，不额外占用槽位。
- 被动满级后从奖励池移除。
- 槽位已满时允许放弃新被动或替换一个已有被动。
- 被替换被动及其等级会失去，必须二次确认。

被动技能可以来自每次角色升级、满级后的击杀奖励和 Boss 特殊奖励。基础属性升级先结算，然后主动/被动技能选择界面暂停模拟。

### 3.16 战斗节奏和可读性约束

数值调试先以战斗时长为目标，而不是只套用血量公式：

```text
普通怪：同等级玩家使用约 2-3 次基础攻击击杀
精英怪：约 8-15 秒击杀
Boss：约 45-90 秒完成一轮战斗
```

Boss 血量需要根据玩家预期每秒伤害、主动技能伤害和战斗阶段反推。每次调整攻击力或技能倍率时，都要重新验证这三个时长目标。

屏幕上的危险信息需要有预算：

- 限制同时存在的敌方弹丸数量。
- 限制同时进行的大型范围技能数量。
- 同一时间尽量只显示一个大型危险区域。
- 高伤害技能必须提供更长或更明显的前摇。
- 使用颜色、形状和音效区分普通攻击、精英技能和 Boss 技能。

无限地图中的 Boss 使用明确的挑战边界：玩家通过入口主动开始，进入有限的 Boss 战斗范围；玩家离开过远时 Boss 脱战或返回入口，但不能通过无限拉扯重置血量和冷却。地图升级后不清除场上已有怪物，只让下一轮生成使用新的地图等级。

### 3.17 数据驱动和调试工具

玩家技能、精英技能和 Boss 技能必须使用数据定义，不在 `GameScene` 中堆叠类型判断：

```ts
interface SkillDefinition {
  id: string;
  cooldown: number;
  windup: number;
  recovery: number;
  range: number;
  damageMultiplier: number;
  targeting: 'direction' | 'nearest' | 'area' | 'dash';
}
```

后续应预留开发调试入口：

- 一键生成普通怪、精英怪和 Boss。
- 一键调整玩家等级、地图等级和技能等级。
- 显示最终攻击力、技能伤害、冷却和怪物出生等级。
- 显示技能前摇和实际命中范围。
- 支持固定随机种子，复现相同的刷怪和掉落结果。

### 3.18 最小垂直切片

在扩展大量内容前，先完成一个完整可玩的闭环：

```text
1 种普通怪
  -> 1 种精英怪
  -> 1 个 Boss
  -> 3 个玩家主动技能
  -> 4 个被动技能
  -> 地图 Lv.1 升到 Lv.2
```

垂直切片必须验证移动、基础攻击、技能冷却、敌方技能预警、Boss 边界、地图经验、奖励选择、重启和暂停。通过后再增加新的怪物、技能和外观变体。

### 3.19 Roguelite 升级奖励闭环

角色从 Lv.1 升到等级上限的每一次升级都提供 3 个候选，选择 1 个后继续游戏。奖励生成器使用可复现的随机源，并遵守以下约束：

- 同一批候选不重复。
- 已满级的主动或被动技能从对应奖励池移除。
- 只要存在可升级的已有技能，尽量保证至少 1 个候选用于强化当前构筑。
- 在主动技能池尚有未学习技能时，尽量保证至少 1 个新主动技能，避免前期只看到数值被动。
- 剩余位置从新主动、主动升级、新被动和被动升级中按权重补足；无法满足“保证”时自动降级为可选候选，不生成空卡或无效选项。
- 新主动技能优先装入空槽；三个槽位已满时，先进入装备替换确认，不在一次点击中直接覆盖。
- 被动槽已满时，允许放弃新被动或二次确认替换；同名被动升级不需要替换。

奖励来源共用同一个 `RewardChoiceSystem`，但使用不同奖励池：

| 来源 | 定位 | 第一版规则 |
| --- | --- | --- |
| 角色升级 | 常规构筑 | 普通主动/被动三选一 |
| 精英技能核心 | 额外加速 | 更偏向已有主动技能升级 |
| Boss 奖励 | 高价值节点 | 高品质、Boss 专属或槽位扩展 |
| 满级后击杀 | 长期成长 | 被动技能、稀有属性或槽位扩展 |

Boss 和满级后击杀奖励可以提供“被动槽扩展”，每次增加 1 格，被动槽位从初始 4 格最多扩展到 6 格；达到上限后该候选自动出池。Boss 奖励中的槽位扩展权重高于普通被动，满级强化中保持中等权重。

一次事件同时触发多个奖励时，按事件顺序把奖励来源请求放入 FIFO 队列，奖励覆盖层显示“待选数量”和奖励来源。候选在请求变为当前奖励时才根据最新技能状态生成，确保前一次选择造成的学习或升级会影响下一批候选。关闭当前选择后立即打开下一个，只有队列清空才恢复模拟。暂停状态必须使用游戏时间，不得让技能冷却、无敌时间、生成器或敌方弹幕在背景继续推进。

第一批主动技能使用 3 级上限，同名技能升级必须同时提升数值和可感知效果：

| 技能 | Lv.1 | Lv.2 | Lv.3 |
| --- | --- | --- | --- |
| 雷电弹 | `1.8x` 伤害、`620` 射程、`3s` 冷却、`72` 半径 `50%` 溅射 | `2.25x`、`670`、`2.82s`、`90` 半径 `65%` 溅射 | `2.7x`、`720`、`2.64s`、`108` 半径 `80%` 溅射 |
| 电光冲刺 | `150` 距离、`4.8s` 冷却 | `180`、`4.55s`，获得 `0.32s` 无敌 | `210`、`4.3s`，获得 `0.52s` 无敌并对路径敌人造成 `80%` 攻击伤害 |
| 雷霆护盾 | 恢复 1 点护盾、`8s` 冷却 | 恢复 2 点、`7.6s` | 恢复 3 点、`7.2s`，施放后 `1.6s` 内受到伤害降低 `50%` |

被动技能第一版也使用 3 级上限：攻击强化和护盾扩容每级 `+1`，移动强化和冷却缩减每级 `+8%`；所有冷却缩减来源最终受 `50%` 全局上限约束。

```ts
interface GameState {
  status: 'menu' | 'playing' | 'paused' | 'reward-choice' | 'boss-challenge' | 'game-over';
  elapsedTime: number;

  player: {
    x: number;
    y: number;
    hp: number;
    maxHp: number;
    shield: number;

    experience: number;
    experienceToNext: number;
    attack: number;

  map: MapProgressionState;
  boss: BossState | null;

  foods: FoodState[];
  monsters: MonsterState[];
  projectiles: ProjectileState[];
```

## 6. Phaser 技术原则

PixiJS 到 Phaser 的运行时迁移已经完成。后续新增玩法不应把规则重新堆回 Scene，而要继续保持模拟、输入、渲染和 HUD 的边界。

### 6.1 Phaser 运行时原则

- 使用 Phaser Scene 管理启动、菜单和游戏生命周期。
- 使用 Phaser 时间系统和统一的 delta 时间驱动游戏计时。
- 使用 Arcade Physics 管理玩家、怪物、食物、子弹和障碍物碰撞。
- 使用 Phaser Camera 建立后续无限世界需要的世界坐标和视口边界。
- HUD、菜单和升级选择默认使用 DOM，Canvas 专注于游戏世界。
- 游戏状态和规则保持在独立 simulation 层，不将 Phaser Sprite 作为唯一状态来源。

### 6.2 时间系统统一

所有战斗、技能、食物和地图进度都使用统一游戏时间，确保暂停、切后台和速度控制行为一致。基础攻击计时、技能前摇、后摇和冷却不能各自维护独立的墙上时间；暂停时攻击计时停止，恢复后继续按剩余冷却推进。

### 6.3 资源预加载

角色和普通怪物资源统一在 Phaser BootScene 中预加载、注册精灵动画；程序化精英怪和 Boss 外观通过可缓存的 Texture 工厂生成，实体进入更新前必须完成视图初始化。

### 6.4 碰撞与渲染解耦

碰撞不应长期依赖 `sprite.getBounds()`。应使用逻辑坐标和明确的 hitbox，渲染层只负责将状态显示出来。

### 6.5 输入集中管理

将移动、目标锁定、方向瞄准、技能、选择、暂停和重启统一映射为 action。目标主映射为 WASD 移动、自动基础攻击、鼠标锁定/瞄准、`Q/E/R` 三个技能槽、`P` 暂停；方向键、`Space`、`J/K/L` 和 `1/2/3` 在过渡期作为兼容映射。物理键可以在不同输入上下文中复用：`R` 在战斗中映射技能 3，只在 `game-over` 上下文映射重启；`1/2/3` 在战斗中映射技能，在 `reward-choice` 中映射候选卡。后续手柄和移动端输入只增加物理映射，不修改技能或奖励规则。

输入层输出归一化 `movementVector`、鼠标世界方向和持久化 `facingVector`。Scene 不应自行用按键优先级判断方向；自动攻击系统负责维护 `currentTargetId`，渲染层只根据方向状态选择四方向动画，技能系统只读取归一化后的目标或方向结果。

### 6.6 实体生命周期

统一处理实体创建、激活、停用、销毁和 ticker 注册，避免重启后重复监听或残留对象。

### 6.7 响应式视口

无限世界需要明确区分屏幕坐标、摄像机坐标和世界坐标，并处理窗口缩放、横竖屏和移动设备尺寸。

### 阶段九：全局地图等级和 Boss 门槛

普通怪和精英怪按地图等级加权刷新：地图 Lv.1 中怪物 Lv.1 / Lv.2 的权重为 `85% / 15%`；地图 Lv.N（N >= 2）中怪物 Lv.N-1 / Lv.N / Lv.N+1 的权重为 `30% / 55% / 15%`。怪物每提升 1 级，最大生命相对种类基础值增加 28%，移速增加 4% 且最高为 `1.35x`，每跨越 4 个等级档位伤害增加 0.5 点；经验基础值按怪物等级倍增。

玩家与地图等级差会修正角色经验和奖励品质，但不修正地图经验。玩家低于地图至少 2 级时经验为 `1.30x`、有效奖励档位 `+1`；等级差为 `-1..+1` 时为 `1.00x`；玩家高 2 / 3 / 4+ 级时经验分别为 `0.70x / 0.45x / 0.25x`，有效奖励档位分别为 `-1 / -1 / -2`。地图每 2 级提升一个基础奖励档位，最高 5 档；当前已实现档位与品质概率契约，具体技能核心和物品掉落池在后续奖励系统中接入。

## 9. 验收标准

### 游戏性

- 玩家可以持续移动和探索，不会因为固定画布边界被迫停止。
- 障碍物会影响路线，但不会造成明显不公平的出生或封路。
- 食物图片与回血语义一致，拾取后只恢复生命且不超过最大生命。
- 受到伤害时先消耗护盾，再消耗血量。
- 击杀怪物可以获得经验，升级后有明确的生存收益。
- 玩家攻击力会随等级提升，主动技能和基础攻击都能对怪物血量造成可计算的点数伤害。
- 普通怪需要多次攻击才能击杀，精英怪和 Boss 具有独立血量规模。
- 主动技能可以通过目标主键位 `Q/E/R` 或备用键 `1/2/3` 释放，并显示明确冷却状态；过渡期保持 `J/K/L` 兼容。
- 基础攻击可以稳定自动选择并保持有效目标；鼠标锁定和方向技能瞄准不影响 WASD 移动。
- 每次升级在基础属性生效后打开三选一，选择期间模拟完全暂停，连续升级不丢失奖励。
- 获得同名主动或被动技能时提升等级和实际效果，已满级技能不再出现在对应候选池。
- 玩家可以八方向移动和攻击，斜向移动速度与直线移动一致。
- 停止移动后保留最近攻击朝向，相反方向同时按住时对应轴正确抵消。
- 精英怪和 Boss 的技能有前摇预警，玩家可以通过走位应对。
- 普通怪、精英怪和 Boss 的战斗时长符合预设目标，屏幕危险信息不会互相遮挡。
- Boss 有明确挑战边界，玩家不能通过无限拉扯重置 Boss 的血量和冷却。
- 被动技能有持有上限，满槽时可以替换已有被动。
- 地图经验满后不会自动提升难度，只有击杀 Boss 才会提高全局地图等级。
- 地图升级只影响之后生成的怪物，场上已有怪物属性不会突变。
- 高等级玩家停留在低等级地图时，角色经验和优质掉落会明显衰减。
- 高地图等级提供更高档位掉落，并适度奖励越级挑战。
- 满级后仍然存在可选择的长期成长。
- 怪物难度提升具有可感知但可应对的节奏。

### 技术性

- 暂停时所有游戏时间、生成器和动画均暂停。
- 重启后不存在重复 ticker、定时器或键盘监听。
- 远离玩家的世界对象会被回收，不会无限增长。
- 游戏状态可以独立序列化，渲染对象销毁不会破坏核心状态。
- 桌面和移动尺寸下 HUD、Canvas 和输入不互相遮挡。
- 技能、敌人和掉落数据可以在不修改 `GameScene` 主循环的情况下扩展。
- 固定随机种子可以复现刷怪、技能和掉落场景。

## 11. Phaser 迁移验收标准

- 现有图片资源可以正常加载，不依赖远程地址。
- 玩家八方向移动速度一致，四方向动画和攻击朝向正确。
- WASD 八方向移动与自动攻击互不干扰；目标选择、子弹方向、出生位置和攻击间隔稳定，鼠标锁定可以覆盖自动选择，`Space` 兼容攻击仍可用。
- 怪物保持追踪行为，碰撞能够结束当前版本的游戏。
- 食物能够随机出现、超时消失并恢复生命。
- 击杀数、开始、暂停和游戏结束 UI 正常工作。
- 暂停时 Phaser 时间事件、物理、动画和生成逻辑都停止推进。
- 重启后不存在重复监听、重复生成器或残留实体。
- 窗口尺寸变化后 Canvas 和 DOM HUD 不重叠、不溢出。
- `yarn build` 成功，浏览器控制台无运行时错误。
- 达到以上条件后，删除 PixiJS 依赖和旧运行时代码。
